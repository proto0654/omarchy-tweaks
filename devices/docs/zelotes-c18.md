# Zelotes C-18 (12c9:2003, SOAI USB Gaming Mouse)

## Что это

Проводная игровая мышь с джойстиком. На этой машине определяется как
`12c9:2003` с именем `SOAI USB Gaming Mouse` и тремя HID-интерфейсами:

| Узел | Что внутри | Как выглядит в системе |
|---|---|---|
| `hidraw0` | обычная мышь: 5 кнопок, колесо, consumer-код `0x0238` | `event2` (мышь) |
| `hidraw1` | эмуляция клавиатуры: полный массив keyboard usages `0x00..0xff`, 3 кнопки, consumer-массив | `event3` (клавиатура), `event4` |
| `hidraw2` | vendor page `0xFF00` | протокол не документирован |

Номера `hidraw`/`event` меняются после переподключения. Ищите устройство по
`idVendor`/`idProduct` и по симлинкам
`/dev/input/by-id/usb-SOAI_USB_Gaming_Mouse-*`.

## 11 кнопок

По паспорту у мыши 11 кнопок. По HID-дескрипторам видно:

- 5 кнопок в `hidraw0` (report 0, usages `0x01..0x05`);
- 3 кнопки в `hidraw1` (report 2, usages `0x81..0x83`);
- джойстик на 5 клавиш: вверх/вниз/влево/вправо и нажатие;
- consumer-код `0x0238` в `hidraw0`.

Это интерфейсные usages, а не обязательно отдельные физические кнопки:
часть из них служебная (DPI/режим), поэтому сумма по интерфейсам больше 11.
Точное соответствие «надпись на
корпусе → код» лучше один раз снять `evtest`: прошивка не документирована.
Джойстик по умолчанию шлёт **W / S / A / D / Space** через клавиатурный
интерфейс, а не отдельные «джойстиковые» коды. Это и позволяет переназначать
его обычными evdev-инструментами.

## DPI

Заявленные уровни: **1500 / 2500 / 4000 / 7000 / 10000 DPI**. Они хранятся в
прошивке мыши; на Linux нет стандартного способа прочитать или выставить DPI
(вендорный протокол `0xFF00` не описан). Если на корпусе есть кнопка DPI, она
переключает профили средствами самой мыши и от ОС не зависит.

Проверить текущий уровень программно нельзя. Практическая проверка —
переместить указатель на одинаковое расстояние и сравнить; для точной
настройки нужна Windows-утилита производителя (или reverse engineering
`hidraw2`, чего в этом репозитории нет).

## Как проверить кнопки и джойстик

```bash
# после установки udev-правила root не нужен
evtest /dev/input/by-id/usb-SOAI_USB_Gaming_Mouse-if01-event-kbd
```

Или интерактивно: `evtest` без аргументов покажет список устройств, выберите
«SOAI USB Gaming Mouse Keyboard». Нажимайте кнопки и смотрите `KEY_*` /
`BTN_*`. Сырые HID-пакеты:

```bash
od -An -tx1 -w16 /dev/hidraw1
```

`hidraw0` — обычная мышь, `hidraw1` — клавиатурная эмуляция (джойстик и
боковые кнопки), `hidraw2` — вендорный канал.

## Как переназначить

Самый простой путь — `keyd`: он видит мышь как отдельное устройство и не
трогает клавиатуру DEXP. Готовый шаблон: `devices/keyd/zelotes-c18.conf`.

```bash
sudo install -Dm644 devices/keyd/zelotes-c18.conf /etc/keyd/zelotes-c18.conf
sudo keyd reload
sudo keyd monitor   # проверить, какие имена шлёт прошивка
```

В шаблоне джойстик переводится в стрелки, боковая кнопка удерживает слой
`zelotes-c18`, вторая боковая кнопка даёт макрос `Ctrl+C`. Замените имена
кнопок (`mouseback`, `mouseforward`, `mouse1`, `mouse2`) на те, что увидите в
`keyd monitor`.

Альтернативы: `input-remapper`, `evremap`, `evdev-rs` — они тоже работают с
`event3`, потому что джойстик шлёт обычные клавиши. Но помните: keyd и
аналоги создают виртуальное устройство; для мыши поддержка в keyd
экспериментальная, и при странном поведении указателя уберите id мыши из
конфигурации.

## libratbag / Piper

В libratbag **нет** устройства `usb:12c9:2003`: в `data/devices/` нет файла с
таким `DeviceMatch`. Поэтому `ratbagctl list` не покажет мышь, а Piper её не
увидит. Это не ошибка установки: libratbag поддерживает Logitech, Etekcity,
GSkill, Roccat, Steelseries и отдельные модели других вендоров, а для Zelotes
нужен новый backend и описание протокола `0xFF00`.

Что можно сделать без libratbag:

- переназначить кнопки и джойстик через keyd (см. выше);
- DPI/подсветку менять Windows-утилитой;
- при желании добавить `.device`-файл и backend в libratbag, но это отдельный
  проект и требует reverse engineering вендорных отчётов.
