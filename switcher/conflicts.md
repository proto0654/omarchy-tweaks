# Конфликт хоткея свитчера с Google Chrome

## Что происходит

Свитчер `text-conv` копирует выделение через `wtype`, инжектируя `Ctrl+C`.
Если в этот момент физический `Shift` ещё зажат, Chrome/Chromium/Electron
получает `Ctrl+Shift+C`. В Chrome это не копирование, а «Inspect element»:
открываются DevTools с выбранным элементом.

## Горячие клавиши Chrome, в которые может попасть инъекция

| Комбинация | Действие в Chrome | Может ли свитчер её случайно вызвать |
|---|---|---|
| `Ctrl+Shift+C` | Inspect element (DevTools, выбор элемента) | Да: `Ctrl+C` при зажатом `Shift` |
| `Ctrl+Shift+I` | DevTools | Нет: свитчер не посылает `I` |
| `Ctrl+Shift+J` | Console (DevTools) | Нет: свитчер не посылает `J` |
| `Ctrl+Shift+M` | Device mode (DevTools) | Нет: свитчер не посылает `M` |
| `F12` | DevTools | Нет: `F12` не входит в хоткеи свитчера |

Дополнительно `Ctrl+Shift+V` в Chrome вставляет текст без форматирования,
а `Ctrl+Shift+Left` выделяет слово. Второе свитчер использует намеренно,
когда выделения нет; к DevTools это не ведёт.

## Что делает этот каталог

`bindings.snippet.lua` переносит срабатывание на **отпускание** клавиши:

- `Shift+Pause` / `Shift+Break` — сменить раскладку выделенного;
- `Alt+Pause` / `Alt+Break` — инвертировать регистр выделенного.

К моменту отпускания `Pause` пользователь обычно уже отпустил модификатор,
поэтому инъекция `Ctrl+C` не превращается в `Ctrl+Shift+C`. Дополнительно
стоит `ignore_mods = true`: маска модификаторов к моменту release может уже
измениться (Shift отпущен раньше Pause), и без этого Hyprland не увидит
привязку. Сам `text-conv` тоже отпускает `shift`, `ctrl`, `alt` и `logo`
перед отправкой `Ctrl+C`/`Ctrl+V`.

## Вывод

DevTools должен открываться **только по `F12`**. Свитчер не должен добавлять
ни одной комбинации, ведущей в DevTools: он посылает только `Ctrl+C`,
`Ctrl+V` и (при отсутствии выделения) `Ctrl+Shift+Left`. Комбинации
`Ctrl+Shift+I`, `Ctrl+Shift+J`, `Ctrl+Shift+M` и `Ctrl+Shift+C` не должны
появляться в его инъекциях; `Ctrl+Shift+C` — единственная реальная опасность,
и её закрывают release-привязка плюс отпускание модификаторов в `wtype`.

Проверка на живой системе:

```bash
bash switcher/verify.sh
```

Скрипт смотрит `hyprctl -j binds`: у четырёх хоткеев должен быть
`"release": true`, а старых press-привязок на тех же клавишах быть не должно.
`hyprctl -j configerrors` при этом обязан быть пустым.
