# Горячие клавиши text-conv в Chrome, Codex и Hermes

## Что происходит

При копировании выделения через `wtype` свитчер отправляет `Ctrl+C`.
Если в этот момент физический `Shift` ещё зажат, Chrome/Chromium/Electron
получает `Ctrl+Shift+C`. В Chrome это не копирование, а «Inspect element»:
открываются DevTools с выбранным элементом.

## Горячие клавиши Chrome, в которые может попасть инъекция

| Комбинация | Действие в Chrome | Может ли свитчер её случайно вызвать |
|---|---|---|
| `Ctrl+Shift+C` | Inspect element (DevTools, выбор элемента) | Да: `Ctrl+C` при зажатом `Shift` |
| `Ctrl+Shift+I` | DevTools | Нет: свитчер не посылает `I` |
| `Ctrl+Shift+J` | Console (DevTools) | Нет: свитчер не посылает `J` |
| `Ctrl+Shift+M` | Device mode (DevTools) | Нет: свитчер не посылает `M` |
| `F12` | DevTools | Нет: `F12` не входит в хоткеи свитчера |

Дополнительно `Ctrl+Shift+V` в Chrome вставляет текст без форматирования,
а `Ctrl+Shift+Left` выделяет слово. Второе свитчер использует намеренно,
когда выделения нет; к DevTools это не ведёт.

## Что делает этот каталог

`bindings.snippet.lua` задаёт два сочетания с точными модификаторами.

- `Shift+Pause` / `Shift+Break` меняет раскладку при отпускании. В Chrome
  это даёт время отпустить Shift, если скрипту потребуется `Ctrl+C`.
- `Ctrl+Pause` меняет регистр при нажатии, пока Ctrl ещё зажат. Сниппет
  использует коды XKB `127` и `419` для Pause и отдельного Break. При
  зажатом Alt вставка через `wtype` превращалась в `Ctrl+Alt+V` и запускала
  голосовой чат Hermes. Ctrl уже входит в сочетание вставки.

В десктопном Codex `Ctrl+Shift+C` копирует путь рабочей папки. Обновлённый
`text-conv` использует `Ctrl+Insert` и `Ctrl+V` через Lua-диспетчер Hyprland
`hl.dsp.send_shortcut`, который задаёт Ctrl явно и проверяет активное окно.

После установки запустите проверку живой конфигурации:

```bash
bash switcher/verify.sh
```

Проверка ищет привязки Shift на отпускание и Ctrl на нажатие и проверяет
отсутствие ошибок конфигурации Hyprland.
